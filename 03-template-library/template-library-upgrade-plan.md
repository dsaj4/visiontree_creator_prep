# 模板库下一步改造方案

更新时间：2026-05-17

## 目标

模板库下一阶段要从“模板条目清单”升级为“创作者开工判断系统”：创作者看到一个模板后，能在 30-60 秒内判断它适不适合当前素材、最终会产出什么、需要准备什么、如何开始使用，以及哪些情况会跑偏。

## 方案一：字段补齐版

适合：快速补齐现有模板，不改目录结构。

新增信息：

- 使用边界：适合什么素材，不适合什么素材，最低输入要求。
- 运行效果：最终产物形态、典型时长、画面/文体气质、交付文件。
- 使用方法：从素材到产物的 3-7 步最短路径。
- 创作者检查点：哪些节点必须人工确认。
- 案例截图：至少 1 张桌面图、1 张移动端图或实际产物图。

优点：改造成本低，能快速同步到 `content-system` 模板卡。

不足：案例复用能力弱，多个项目案例容易挤在模板正文里。

## 方案二：创作者运行手册版（推荐）

适合：把模板库作为创作者真正开写、开做前的工作台。

目录结构：

```text
03-template-library/
├── template-index.md
├── template-library-upgrade-plan.md
├── tpl-xxx.md
└── examples/
    └── case-name/
        ├── README.md
        └── screenshots/
```

模板正文新增固定模块：

- 一句话用途：这个模板帮创作者解决什么问题。
- 使用边界：适用、慎用、不适用。
- 输入要求：原文、素材、账号语气、视觉参考、发布渠道。
- 运行效果：最终产物、内容结构、视觉或语气结果。
- 使用方法：最小可执行流程。
- 质量判断：好结果长什么样，坏结果的预警信号。
- 最新案例：链接到 `examples/` 下的案例页。
- content-system 映射：哪些字段进入前台模板库，哪些只留在准备区。

案例页记录：

- 项目背景：素材类型、目标受众、发布场景。
- 产物清单：脚本、分镜、样式、网页工程、截图、录屏口径。
- 运行效果：章节数、step 数、交互方式、适配情况。
- 使用边界复盘：这个案例证明模板擅长什么，不擅长什么。
- 可迁移方法：下次复用时可以直接照搬的做法。

优点：模板保持干净，案例能沉淀为真实例证；创作者既能快速判断，也能深看案例。

不足：需要维护模板和案例两层资料。

## 方案三：模板变体矩阵版

适合：同一个模板需要服务多个账号、渠道和内容气质时。

新增信息：

- 账号变体：同一模板在 `milo`、`thinking-lab`、`visiontree` 等账号下的写法差异。
- 内容变体：解释型、复盘型、教程型、发布型、观点型。
- 风格变体：纪录片、产品 talk、技术拆解、课堂讲解、视觉随笔。
- 禁用组合：例如官方号不抢个人叙事，个人号不写成公司 PR。

优点：能防止跨账号写串号。

不足：需要足够多真实案例支撑，适合第二阶段再扩展。

## 确定采用

当前采用“方案二：创作者运行手册版”，先为 `tpl-garden-web-video-presentation` 补上真实案例。后续若一个模板出现 3 个以上账号差异化案例，再叠加“方案三”的变体矩阵。

## 对 content-system 的影响

- 前台模板库仍同步轻量字段：`title`、`format`、`channels`、`hook`、`structure`、`length`、`notes`、`resources`。
- 使用边界、运行效果、使用方法、案例截图可被整理进 `notes` 和 `resources`。
- 完整案例页暂时保留在 `creator-prep-workspace`，不直接塞进前台卡片。
