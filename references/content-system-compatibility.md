# Content System 兼容规范

更新时间：2026-05-17

本规范要求 `creator-prep-workspace` 的所有产物都能兼容 `content-system` 的素材池、模板库和个人主页。

## 1. 素材池兼容

素材卡必须可映射到 `assets`：

| 本工作区 | content-system |
| --- | --- |
| 素材卡 ID / assetId | `id` |
| 标题 | `title` |
| 主题 | `theme` |
| 来源 | `source` |
| 格式 | `format` |
| 新鲜度 | `freshness` |
| 优先级评分 | `score` |
| 标签 | `tags` |
| 创作摘要 | `summary` |
| 适合账号 / owner | `owner` |
| 视觉标识 | `palette` |
| 使用提示和误用边界 | `notes` |
| 原始资料链接或文件 | `resources` |

主动更新触发条件：

- 来源不完整。
- 摘要不能直接帮助创作。
- notes 缺少“适合怎么用”或“不要怎么误用”。
- 适合账号或标签不准确。

## 2. 模板库兼容

模板必须可映射到 `templates`：

| 本工作区 | content-system |
| --- | --- |
| 模板 ID / templateId | `id` |
| 模板名 | `title` |
| 内容类型 | `format` |
| 渠道 | `channels` |
| 结构步骤 | `structure` |
| 开场方式 | `hook` |
| 建议长度 | `length` |
| 使用提示和禁忌 | `notes` |
| 参考资料 | `resources` |

主动更新触发条件：

- 模板不能体现账号差异。
- `structure` 不够可执行。
- 缺少适用素材或禁忌写法。
- 同一主题在多个账号上出现同质化表达。

### 2.1 前端展示映射设计

`content-system` 前端展示的是给创作者用的模板卡，不展示“数据库字段感”。映射时按“快速判断 -> 决定套用 -> 深看案例”的顺序组织。

#### 列表卡片

| content-system 字段 | 前端含义 | 展示建议 |
| --- | --- | --- |
| `title` | 模板名称 | 12-24 字，直接说明产物，不用内部代号 |
| `format` | 产物形态 | 显示为类型标签，例如“网页视频 / 工具流程” |
| `hook` | 一句话用途 | 1 句话说明“用它能做成什么” |
| `channels` | 可用渠道 | 展示 3-6 个渠道标签，过多时合并为“多平台” |
| `length` | 工作量和产物长度 | 用创作者能判断成本的说法，例如“3-8 分钟视频；4-8 章” |
| `structure` | 开写路径 | 最多展示 5 个短步骤，作为可扫读 chip |
| `referenceCount` | 已发布引用 | 由系统计算，仅作信任信号，不在准备区手写 |

#### 详情页

| 展示模块 | 来源字段 | 文案目标 |
| --- | --- | --- |
| 能做什么 | `hook` + `format` | 让创作者立刻知道最终产物长什么样 |
| 适合什么素材 | `notes` 中的 `适用范围` / `准备输入` | 判断手头素材是否够用 |
| 不适合什么 | `notes` 中的 `使用边界` | 防止误套模板 |
| 怎么开始 | `structure` + `notes` 中的 `操作方式` | 给出最短执行路径 |
| 运行效果 | `length` + `notes` 中的 `运行效果` | 说明产物节奏、结构、交互或视觉结果 |
| 验收方式 | `notes` 中的 `验收方式` | 告诉创作者什么时候该停下来人工确认 |
| 最新案例 | `resources` 中的案例资源 | 用真实项目帮助创作者理解使用边界 |

#### notes 写法规范

`notes` 进入前端后会被直接展示或按冒号前缀分组，所以每条必须是完整、友好的创作者提示。推荐固定前缀：

- `标签：` 用于说明模板属性，例如工具 / 流程。
- `适用范围：` 说明什么素材适合用。
- `准备输入：` 说明开始前必须准备什么。
- `使用边界：` 说明不能怎么用。
- `操作方式：` 给出最短执行路径。
- `运行效果：` 描述最后产物的结构、节奏、画面或交互。
- `验收方式：` 标出人工确认点。
- `最新案例：` 指向真实项目及其证明了什么。
- `同步边界：` 说明哪些内容只留在准备区，不进前台。

避免写法：

- 避免“该字段映射到某数据库列”这类后台话术。
- 避免只写“详见文档”，必须在前端卡片里给出最小可用判断。
- 避免把完整工作流塞进一条 note，每条只表达一个判断。
- 避免承诺工具已自动执行完整生产，除非 content-system 已具备对应能力。

#### resources 写法规范

`resources` 在前端用于支撑“这个模板为什么可信、哪里能看案例”。每个资源建议包含：

- `title`：资源名，优先写真实案例或来源名称。
- `kind`：当前前端支持 `web` / `pdf`；本地准备区资料先按 `web` 作为资料卡展示。
- `url`：可打开链接；本地路径无法在前端直接打开时，先放来源项目或仓库链接。
- `source`：来源类型，例如 `creator-prep-workspace`、`GitHub`、`B 站来源资料`。
- `updated`：资源更新时间。
- `summary`：一句话说明这个资源能帮创作者判断什么。
- `highlights`：3 条以内，写运行效果、边界或可迁移方法。

#### 推荐前端顺序

1. 顶部：`title`、`format`、`channels`、`length`。
2. 主说明：`hook`。
3. 快速判断：适用范围、准备输入、使用边界。
4. 开始使用：`structure` + 操作方式。
5. 结果预期：运行效果、验收方式。
6. 真实例证：最新案例和资源。

#### 当前实现状态

- 实现日期：2026-05-17
- 影响模块：`content-system` 模板库前端详情页、模板种子数据、`creator-prep-workspace` 模板库规范。
- 已实现：模板详情页单独使用创作者展示结构，不再复用素材详情的“创作提示”堆叠方式。
- 已实现分区：创作者快速判断、开始使用、运行效果与验收、真实案例与来源。
- 已实现解析方式：前端按 `notes` 冒号前缀自动分组；未纳入固定分区的前缀会以原前缀标题展示，无前缀内容进入“其他提示”。
- 同步边界：当前只改变模板卡展示和种子文案，不改变数据库表结构；完整案例、脚手架、截图源文件仍保留在准备区。

## 3. 个人主页兼容

账号人设必须可映射到 `users` / persona：

| 本工作区 | content-system |
| --- | --- |
| 账号名 | `accountName` |
| 展示名 | `displayName` |
| 负责人 / 角色 | `role` |
| 平台 | `platform` |
| 平台 handle | `handle` |
| 主页链接 | `profileUrl` |
| 账号定位 | `positioning` |
| 人设作用 | `personaRole` |
| 声音关键词 | `voice` |
| 内容类型 | `contentTypes` |
| 禁忌写法 | `avoid` |
| 发布节奏 | `cadence` |
| 互动对象 | `interactionTarget` |

主动更新触发条件：

- 主页资料和账号定位不一致。
- 人设说明不能指导创作者。
- 语气边界不清导致多个账号声音趋同。
- 内容类型、发布节奏或互动对象发生变化。

## 4. 同步状态

每个素材、模板、人设产物都必须标记：

- `未同步`：只在准备区存在。
- `待同步`：已整理完成，建议更新到 `content-system`。
- `已同步`：已经进入 `content-system`。
- `不同步`：仅作为内部参考，不进入系统。
